# StoryEditor

**線上使用：https://zz32569469.github.io/StoryEditor/**

不需安裝、不需帳號，開網頁就能用。所有資料都留在你的瀏覽器裡，不會上傳到任何地方
（自動存檔存在 localStorage，專案檔與 Excel 都是本機下載／上傳）。

遊戲劇情／對話編輯器。**編輯器跑在網頁，播放器在 Unity**，兩端以一份平台無關的 `.story.json` 為契約。

- 支援分支選項、條件、變數的完整對話系統
- 文字特效以內嵌標記表示，網頁預覽與 Unity 共用同一份標籤定義
- Excel（`.xlsx`）**雙向同步**：匯出給編劇／翻譯修改，改完匯回並以三方合併處理衝突

資料格式規格見 [`docs/FORMAT.md`](docs/FORMAT.md)。

## 本機開發

```bash
npm install
```

| 指令 | 用途 |
|---|---|
| `npm run dev` | 開發伺服器 |
| `npm test` | 跑測試 |
| `npm run typecheck` | 型別檢查 |
| `npm run gen:schema` | 由 Zod schema 重新產生 `docs/story.schema.json`（改 schema 後必跑） |
| `npm run convert -- <來源.xlsx> [輸出.story.json]` | 把既有劇本表格轉成專案檔，見下 |
| `npm run build` | 產出靜態網站 |

## 兩種 Excel，別搞混

| 按鈕 | 用途 | 對象 |
|---|---|---|
| **匯入／匯出劇本 xlsx** | 完整劇本表，原本的欄位與編號 | 既有製作流程 |
| **匯入／匯出翻譯表** | 只含可翻譯文字，靠隱藏 `row_key` 逐格三方合併 | 譯者、校對 |

翻譯表**讀不懂**劇本 xlsx，反之亦然。餵錯了會直接告訴你，不會靜默失敗。

### 劇本 xlsx 格式

每張工作表 = 一個場景，`ID` 為表內流水號，`跳轉` 指向同表的 ID。

| 標誌 | 意義 |
|---|---|
| 空白 或 `#` | 一般台詞 |
| `q` | 選項，同「組」為一組 |
| `if` | 條件分支，同「組」為一組 |
| `set` | 變數賦值 |
| `in` | 等待玩家輸入 |
| `end` | 場景結束 |

**匯入 → 匯出是原樣往返的**：同樣的工作表、欄位順序、ID 與跳轉編號。
編輯器新增的內容才配發新編號（接在該表現有最大值之後）。

**但格式不還原** —— 儲存格色彩、欄寬、合併儲存格這些都不會保留，只有內容。

`q` 與 `if` 群組會各自成為**一個節點**，而不是掛在跳進來的那個節點上：實際劇本中
有多個節點跳進同一個群組（對話 hub），複製選項會讓 id 出現多份。同組成員各自的
人物、跳轉與製作欄位都獨立保存。

沒有對應欄位的製作資訊（OST、畫面效果、屬性變化、背景、插圖…）原樣存進
`extras`，顯示在節點編輯面板底部，匯出時寫回原欄位。

也可以用命令列批次處理：

```bash
npm run convert -- "C:\path\to\script.xlsx"
```

## 進度

| | 內容 | 狀態 |
|---|---|---|
| M0 | 資料格式、Zod schema、Excel 欄位規格、tagRegistry | ✅ |
| M1 | 編輯器介面（即時預覽 + 編輯面板）、專案檔存讀、xlsx 匯出匯入 | ✅ |
| M2 | tag parser、逐字播放預覽 | ✅ |
| M3 | 條件求值、變數系統、從頭播放 | ✅（節點圖未做） |
| M4 | Excel 三方合併與衝突 UI | ✅ |
| M5 | Unity runtime 套件 | 待做 |
| — | 既有劇本 xlsx 的原樣往返匯入匯出 | ✅ |

M2 與 M1 合併實作 —— 預覽是使用者判斷特效對不對的唯一途徑，不能等到編輯器之後才做。
M4 提前完成，因為「匯入會不會吃掉我的修改」是這個工具最關鍵的信任問題。

預覽區的「▶ 從頭播放」會真的求值條件、套用賦值、依選項跳轉，用來驗證分支走不走得通。
變數面板可以當場改值試不同路徑；`<age>` 這類插值會換成當下的變數值。

M3 尚未做的部分：分支結構仍以下拉選單編輯，沒有視覺化節點圖。

## 技術選型摘要

| 用途 | 選擇 | 理由 |
|---|---|---|
| Excel | ExcelJS | npm 上的 `xlsx` 停在 2022 年且帶未修補 CVE；且我們需要凍結列／隱藏欄／底色 |
| 驗證 | Zod 4 | schema 即契約，可 `z.toJSONSchema()` 產出給 Unity 對照 |
| id | ULID | 見 `docs/FORMAT.md` §0 —— id 不可變是雙向同步的地基 |

> `npm audit` 會回報 ExcelJS 傳遞相依 `archiver` 底下 glob/minimatch 的 DoS 告警。觸發條件是攻擊者可控的 glob pattern，本專案不會傳入；降版到 `exceljs@3` 是破壞性變更，故不處理。
